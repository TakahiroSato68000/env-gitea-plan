# 実証検証 実施計画

## 1. 目的

Gitea を用いたソース管理および Windows ビルド環境について、初期導入の成立性を確認する。

本実証検証では、以下を確認対象とする。

- Windows 上の WSL2 Linux 環境で Gitea を運用できること
- Windows 側でビルド実行環境を構築できること
- 共有 NuGet フォルダのみで restore / build が成立すること
- 古い Windows アプリのビルドに適用可能であること
- 将来のビルド実行環境分離に支障がない構成であること

---

## 2. 検証対象

### 対象

- Gitea の起動および基本操作
- Windows 上のビルド実行環境
- WSL2 Linux 環境上のコンテナ実行環境
- 共有 NuGet フォルダ運用
- Gitea runner を用いた自動ビルド実行

### 対象外

- 本番向け高可用性構成
- 本格的な監視・バックアップ運用設計
- 大規模利用を前提とした性能評価
- 社内 NuGet リポジトリの導入

---

## 3. 前提条件

- Windows マシン 1 台を利用可能であること
- WSL2 を利用可能であること
- Gitea を WSL2 Linux 環境上で動作させること
- Windows 側にビルドツールを導入できること
- 共有 NuGet フォルダにアクセスできること
- 対象となる既存ソリューションまたはサンプルソリューションを用意できること

---

## 4. 検証構成

### Windows 側

- Gitea runner
- Visual Studio Build Tools
- MSBuild
- NuGet
- ビルド対象ソリューション
- 共有 NuGet フォルダアクセス

### WSL2 Linux 側

- Gitea
- Linux 側 Engine によるコンテナ実行環境

---

## 5. 実施項目

| 項目 | 確認内容 | 判定基準 |
|---|---|---|
| Gitea 基本動作 | 起動、画面接続、管理者作成、リポジトリ作成、push/pull | 基本操作が問題なく実施できる |
| Windows ビルド環境 | Git、NuGet、MSBuild、必要な targeting pack の確認 | 手動で対象ソリューションをビルドできる |
| 共有 NuGet フォルダ | 共有フォルダ参照、`NuGet.Config` 設定、restore 実行 | 共有フォルダのみで restore が成功する |
| 自動ビルド | runner 登録、job 実行、restore/build 実行 | 自動ビルドが成功する |
| 再起動後確認 | Windows 再起動後の Gitea、runner、ビルド再実行 | 再起動後も同様の処理が可能 |

---

## 6. 成功条件

以下を満たした場合、本実証検証は成立と判断する。

- Gitea が WSL2 Linux 環境上で継続利用可能であること
- Windows 側で対象ソリューションのビルドが可能であること
- 共有 NuGet フォルダのみを用いた restore が可能であること
- Gitea runner による自動ビルドが成功すること
- Windows 再起動後も再度同様の処理が可能であること

---

## 7. 想定リスク

- WSL2 環境の再起動後復帰手順が不明確になる可能性がある
- Build Tools の構成不足によりビルドできない可能性がある
- 共有フォルダ内のパッケージ不足により restore に失敗する可能性がある
- 同一マシン上で Gitea とビルドを動作させるため、負荷競合が発生する可能性がある

---

## 8. 実施後の判断

実証検証結果をもとに、以下を判断する。

- 初期構成としての導入可否
- 必要な追加設定の有無
- ビルド実行環境分離の優先度
- 今後の運用手順書整備の必要性

---

## 9. 次段階

実証検証が成立した場合、次の段階として以下を進める。

- Windows runner 導入手順の整備
- WSL2 + Gitea 構築手順の整備
- NuGet 共有フォルダ運用手順の整備
- 対象ソリューションへの適用拡大
- 将来のビルド実行環境分離計画の具体化
