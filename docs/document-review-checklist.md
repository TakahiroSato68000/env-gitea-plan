# 文書横断レビュー観点一覧

## 1. 目的

本資料は、本リポジトリ内の各 Markdown 文書を横断的に見直す際の観点を整理するためのチェックリストである。

文書追加や改訂のたびに、本観点に沿ってレビューすることで、方針の一貫性、表現の統一、運用上の抜け漏れを抑えることを目的とする。

---

## 2. 方針の一貫性

以下の基本方針が各文書で矛盾なく記載されているかを確認する。

- ソース管理は Gitea を採用する
- Gitea は Windows 上の WSL2 Linux 環境で運用する
- コンテナ実行には Linux 側 Engine を用いる
- Docker Desktop は今回は採用しない
- ビルドは Windows 側で実施する
- NuGet は共有フォルダ運用とする
- 初期は 1 台構成で実証検証を行う
- 将来的にビルド実行環境を分離する

確認事項:

- 文書ごとに前提が変わっていないか
- 一部文書だけ別構成を示していないか
- 将来構成と初期構成が混在していないか

---

## 3. 用語統一

以下の用語が一貫して使われているかを確認する。

- 実証検証
- ビルド実行環境
- 共有 NuGet フォルダ
- Linux 側 Engine
- Windows runner
- WSL2 Linux 環境
- 初期構成
- 将来構成

確認事項:

- 同じ意味の語が文書ごとに揺れていないか
- カタカナ表記、英語表記、日本語表記が混在していないか
- runner / Runner など表記ゆれがないか

---

## 4. 文体・構成統一

各文書の読みやすさを確保するため、文体と構成がそろっているかを確認する。

### 文体

- 原則として「〜する」調で統一されているか
- 説明調と手順調が不自然に混在していないか
- 上司向け説明文として過度に技術寄りになっていないか

### 構成

可能な範囲で以下の構成がそろっているかを確認する。

- 目的
- 前提条件
- 構成または手順
- 留意事項
- 次段階

確認事項:

- 見出しの粒度が大きくずれていないか
- 項番の振り方が統一されているか
- 箇条書きの書式が統一されているか

---

## 5. 運用上の抜け漏れ

技術手順だけでなく、運用上必要な観点が抜けていないかを確認する。

- 再起動後の復帰確認
- アクセス権・権限設定
- 共有フォルダ権限
- runner 実行アカウントの権限
- バックアップ対象
- 将来の役割分離前提
- ログ保管先
- 障害時の切り分け観点

確認事項:

- 手順はあるが運用観点が抜けていないか
- 初期導入と継続運用の両面が最低限押さえられているか
- 依存する共有資源の管理責任が曖昧になっていないか

---

## 6. 技術的な確認ポイント

各文書に必要な技術観点が盛り込まれているかを確認する。

- Build Tools 構成
- .NET Framework targeting pack
- NuGet source 固定
- 共有フォルダ参照可否
- runner 実行アカウント権限
- ポート設定
- Gitea 接続確認
- restore / build の成功確認
- 再起動後の再実行確認

確認事項:

- 手順が抽象的すぎて作業できない状態になっていないか
- 重要な前提条件が明記されているか
- 実施後の確認項目が定義されているか

---

## 7. 文書間の整合性

複数文書の間で参照関係や内容の整合が取れているかを確認する。

- README の文書一覧が最新であること
- 読む順番が内容と整合していること
- 各文書の前提条件が README の説明と整合していること
- 他文書への参照名が正しいこと
- 追加した文書が README に反映されていること

確認事項:

- ファイル名変更後のリンク切れがないか
- 文書追加後に README が更新されているか
- 同じ事項が複数文書で矛盾していないか

---

## 8. レビュー時のチェックリスト

以下をレビュー時の実務チェックリストとして用いる。

- [ ] 基本方針に矛盾がない
- [ ] 用語に表記ゆれがない
- [ ] 文体が「〜する」でおおむね統一されている
- [ ] 見出し構成が大きく崩れていない
- [ ] 初期構成と将来構成が整理されている
- [ ] 運用上の留意事項が記載されている
- [ ] 技術的な確認ポイントが不足していない
- [ ] README の一覧とリンクが最新である
- [ ] 文書間の参照関係に矛盾がない
- [ ] 上司向け説明資料として読める粒度を維持している
